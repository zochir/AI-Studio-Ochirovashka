# AI Comic Studio — локальная генерация и расширяемая архитектура

## Принцип проекта

Основной путь проекта — **local-first**: изображения в первую очередь создаются на компьютере пользователя локальной моделью с открытыми весами. Облачные API — только необязательный адаптер на будущее, а не обязательное условие работы и не основа продукта.

Пользователь сейчас работает с телефона, поэтому разработку и сборки нужно продолжать через GitHub и облачные инструменты. Установка локального движка на компьютер не должна быть предварительным условием для продолжения разработки приложения.

## Целевая схема

1. **Android-приложение** — интерфейс для задания истории, персонажей, стиля, раскадровки, очереди генерации, просмотра результатов и экспорта.
2. **Локальный движок на компьютере** — ComfyUI или совместимый сервер генерации, запускающий модели на доступном GPU/CPU. Приложение отправляет задания движку и получает статусы и изображения.
3. **Модели** — подключаемые локальные модели text-to-image; выбор конкретной модели зависит от видеопамяти, лицензии и качества. Не зашивать единственную модель в приложение.
4. **Персонажи и стиль** — библиотека референсов и описаний; далее поддержка IP-Adapter/ControlNet/LoRA там, где выбранная модель и workflow это позволяют.
5. **Очередь заданий** — пакетная генерация кадров, отображение прогресса, повтор после временных ошибок и возможность продолжить незавершённую работу.
6. **Сборка комикса** — макеты страниц, панели, пузыри реплик, подписи, управление порядком кадров и экспорт в PNG/PDF/архив проекта с исходными изображениями.
7. **Расширение** — анимация и видео отдельными подключаемыми модулями после надёжной работы статичных комиксов.

## Экономика и честные ограничения

- При локальной генерации нет обязательной платы за каждое изображение или API-токены, но нужны электричество, подходящее оборудование и место для моделей.
- «Бесплатно и без ограничений» нельзя обещать без оговорок: скорость и разрешение ограничиваются оборудованием, памятью, лицензиями и выбранными моделями.
- Облачная генерация должна быть необязательной. Если её добавят, пользователь должен явно видеть, какой провайдер используется и возможна ли оплата.
- API-ключи не должны встраиваться в APK или храниться в открытом виде. Для локального движка нужно отдельно продумать безопасное подключение по домашней сети и доступ извне.
- Пока локальный движок не подключён и не выполнена реальная генерация, тесты с имитацией API не считаются подтверждением работы генерации.

## Этапы реализации

### Этап 1 — приложение и тестируемый интерфейс
- Стабильная сборка APK и smoke-test запуска.
- Сценарий, раскадровка, карточки кадров и сохранение проекта.
- Отдельный интерфейс подключения движка; облачный OpenAI-compatible endpoint не должен быть единственным путём.

### Этап 2 — локальный движок
- Добавить адаптер ComfyUI API: отправка workflow, получение prompt/job ID, опрос статуса, получение итоговых изображений и обработка ошибок.
- Workflow должен быть настраиваемым: узлы и названия входов отличаются между моделями.
- Добавить проверку соединения и понятную диагностику адреса, сети, CORS и доступности движка.
- Протестировать адаптер с имитацией API, затем отдельно — с реально запущенным ComfyUI и моделью.

### Этап 3 — готовый комикс
- Передавать в генератор описание сцены, общий стиль и референсы персонажей.
- Сохранять сами изображения в проекте, а не только внешние URL.
- Экспортировать страницы с изображениями и репликами в переносимый формат.

### Этап 4 — расширение
- Управление несколькими workflow и моделями.
- Стабилизация персонажей через референсы и совместимые методы адаптации.

## Текущее состояние

Текущий APK-модуль умеет создавать текстовую раскадровку локально, обращаться к совместимому Chat Completions API без обязательного ключа, подключать OpenAI Images API и отправлять API-workflow в ComfyUI с опросом истории задания. Эти пути проверены только автоматическими тестами с имитированными ответами; реальная генерация на запущенном движке и реальном устройстве ещё не подтверждена. SVG-экспорт пытается встроить изображения, но загрузка изображений с локального ComfyUI может блокироваться политикой CORS, а SVG содержит foreignObject, который поддерживается не всеми просмотрщиками. Следующие инженерные задачи — подтвердить запуск APK в эмуляторе, проверить реальные ComfyUI-запросы, обеспечить сохранение изображений в переносимом проекте и добавить надёжный экспорт PNG/PDF.
